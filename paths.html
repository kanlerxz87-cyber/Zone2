How to read this

Each path is the board's own options, re-cut into a sequence. A letter in the map below is a real row on the board: SG-01 A means suggestion SG-01, option A, with the trade-off that the board already states. Where a path says same as Path 1, the board's recommendation stands unchanged — the path does not quietly reopen it.

Recommendation: Path 1 is the default, because it is exactly the set of recommendations already on the board and it needs no answer to proceed. If nothing is recorded, this is what the site already is.

The three paths

One line each, then the detail. Cost and risk are judgements built on the cited rules, not program facts.

Path 1 · publish clean

Ship the verified research site, no commissionable links.

The site publishes as evidence: every product attribute either linked to the page it was read from or left blank, the open questions visible, the flagged items on the record. Content stays data-led (SG-05 A) with no claim that anyone used a product, no prices (SG-03 A), no ratings (SG-07 A).

Cost: no affiliate revenue while it runs like this, because no link on the site carries an Associates tag — that is F-24, and it is a property of the links, not a design choice.
Risk: the lowest available. There is nothing here for the program rules to bite on: no price display, no rating display, no testing claim, no attribution claim.
Waits on: nothing. It is the board's recommendation set, unchanged.

Record Path 1 on the board

Path 2 · earn

Put the owner's own tagged links on the strongest buyer-intent pages.

Everything in Path 1, plus: SG-04 B (the head-to-head of the three products, the page with the highest purchase intent and the one blocked until the identifiers are confirmed), SG-05 B (hands-on writing only where a dated test record exists), and SG-08 B (planning against one named commission band, once Amazon's own category for each ASIN is known).

Cost: one thing, and it is not code — an approved Associates account, the ASINs confirmed by their owner, and links minted in that account (Application Review Process: “Associates special links are the identifiers … embedded in Amazon product links on the site(s) declared in your application”).
Risk: low if, and only if, the account is real and the links are re-minted. A link copied from somewhere else points the commission at whoever minted it.
Waits on: Q-02 (approved account and ID), Q-03 (the actual ASINs), Q-18 (who created the three supplied links), Q-11 (a test record), Q-08 (the band), Q-04 (a site the owner owns).

Path 3 · automate

Switch on the data the platform was specced around — through Amazon's own API.

Everything in Path 2, plus SG-03 B (dated price snapshots obtained through the Creators API, never tracked or alerted on), SG-07 B (ratings and review counts from the same API, with their date), SG-02 B (widening from three products to a category once a permitted demand source exists) and SG-09 C (site analytics layered on the per-page static sub-tags, after a privacy review).

Cost: an eligibility threshold first — the Creators API documentation lists ten qualifying sales in the past thirty days before it is available, which is a revenue gate, not a technical one. Then the build.
Risk: medium. This is the only path where the platform's own automation touches program content, so every module has to stay inside the rules in the compliance ledger.
Waits on: Q-02, Q-09 (written agreement for anything resembling price tracking), Q-12, Q-13 (an authorised demand source).

The launch bar you have to clear

Read from Associates Central → Application Review Process, fetched again for this page on 2026-11-15. Quoted, not paraphrased, because the wording is the requirement.

What Amazon statesWhy it changes a decision here
“our Associates team will check your application once you've driven qualified sales (we require at least three within the first 180 days). Please note that personal orders do not qualify.” You are approved by performing, not by applying. So Path 1 has to be live and good enough to sell before Path 2 exists at all — the sequencing on this page follows from this sentence.
“All Sites must have robust original content (even when advertising is removed) – a good rule of thumb is at least 10 posts. They must be publicly available.” A thin affiliate site is not merely unattractive, it is ineligible. The verified articles are the asset that clears this, which is why the content layer is in Path 1 rather than saved for later.
“Content on your website must be recent (generally within the last 60 days). You must own your website.” Two obligations with dates attached: a re-verification cadence for the content, and a domain question (Q-04) that a project path on a hosted pages service does not obviously answer.
“Unfortunately, we aren't able to reassess an application once it's been rejected.” Rejection is terminal. Anything that reads as thin, unowned or unattributed is not a soft penalty — it forecloses the account Path 2 needs. This is the single strongest argument for shipping Path 1 properly first.
Accepted social networks are listed by name, must be given as an exact URL, and “must be established, with a substantive number of organic followers/likes (in most cases, at least 500)”. The organic-traffic plan can only claim channels that exist and are large enough to declare. A distribution channel that cannot be declared cannot be relied on.

Recording a choice

One row per suggestion, one field: decision in ledger/suggestions.json. Choosing Path 2 means recording "decision": "B" against SG-04 and SG-05, and "A" against the rows where the default stands. The board is the record; this page is the reading of it. Nothing is implemented until the field says so, and an implementation batch ships as one commit, rebuilt and checked — that is SG-10 A, which is why the paths can be reversed as cheaply as they can be taken.

If a path is picked while its questions are still open, the honest outcome is that the blocked rows stay blocked: Q-02, Q-03 and Q-18 are not paperwork, they are the difference between a link that pays you and a link that pays somebody else.
