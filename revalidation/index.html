What this session did

The repository already contained a published conclusion that the three supplied link.amazon links land on arbitrary fallback pages which cannot identify a product. That conclusion rested on two observations: the redirects carry plpRedirect=mhFallback, and a re-fetch was reported to change the page body and the btn_ref token. Neither observation had a control. This session ran the control, and it does not support either.

The correction is narrow but material: the destination products are real, stable and individually tracked — not random — while the short codes themselves remain non-ASINs. What was wrong was the reasoning that joined the two facts.

The two tests that changed the conclusion

C-1 · Is plpRedirect=mhFallback evidence of a fallback?

A bare, untagged, direct request to the product page of a valid 10-character ASIN was made on www.amazon.com. Amazon answered with the full, correct product page and rewrote its own internal links to carry plpRedirect=mhFallback. 

GET https://www.amazon.com/dp/B08DKYBTPH          (bare request: no tag, no short link)
200 -> CHEFMAN 8 Qt TurboFry product page, buy box + About this Item rendered
final URL -> https://www.amazon.com/dp/B08DKYBTPH?lv=shuf&channelId=500&plpRedirect=mhFallback&th=1

Result: the marker appears on ordinary product pages. It does not separate a valid ASIN from an unaddressable code, so it cannot support the published inference.

C-2 · Does the destination really shuffle between requests?

The same short link was fetched twice. Both responses resolved to the same ASIN with the identical per-link token. 

GET https://link.amazon/B04G1MEwY   (fetch 1)
GET https://link.amazon/B04G1MEwY   (fetch 2)

both -> /dp/B0CDY277D3?lv=shuf&btn_type=ss&btn_ref=srctok-1e229870efde5acf&channelId=704&plpRedirect=mhFallback
        same ASIN · same token · same page body

Three different submitted links produced three different stable tokens. That is the signature of per-link tracking, not of a shuffle.

What is still not established

The links resolve deterministically, but no public Amazon document binds a link.amazon short code to a destination ASIN. The mapping is therefore observed behaviour, not documented intent, and none of the three resolved URLs carries an Associates tag. Both points remain flagged (RV-02, RV-03) for confirmation in Associates Central. The products on this site are described as the product each link resolves to, never as the product you selected.
