Design notes

Why this site is built the way it is — and what we would change next

An affiliate site lives or dies on whether a reader trusts it enough to click. This page records the design reasoning: what the previous layout got wrong, what the redesign does instead, which design decisions have an official source behind them, and which improvements are proposed but deliberately not implemented — waiting for a recorded decision on the suggestions board.

Affiliate disclosure: As an Amazon Associate I earn from qualifying purchases.

The diagnosis: it read like a back-office, not a storefront

The previous design was an admin dashboard: a default-blue sidebar, dense cards, KPI tiles, and walls of procedural prose. That presentation is right for an internal tool and wrong for a marketing site — a visitor met the verification machinery before the products, and every page looked like a settings screen. The substance was sound; the presentation was the problem.

What changed in the redesign (all implemented in this release):

  • A marketing frame, not a console. A sticky dark header with a horizontal nav replaced the sidebar; pages now open with a proper hero that states the page’s promise in one sentence, instead of a small heading and a paragraph of caveats.
  • Products first. The landing page now leads with the three resolved products as cards — brand, listing title, category path, the honest blanks for price and rating — before any verification narrative.
  • An editorial voice. Fraunces (display serif) over Inter, a warm paper background with an ember accent, and human sentences in place of boilerplate. The tone is the trust strategy: “blank means unverified, never guessed” is the brand.
  • Honesty as design. Unverified cells render as a distinct, styled unverified mark — legible at a glance rather than lost in a table. Flags got a preview section on the landing page, rendered from the same ledger as the register.
  • Decisions as a first-class section. The landing page links the suggestions board, the open-questions register and these design notes, so a reviewer can see the queue of ideas before anything ships.
  • One system everywhere. The generated evidence views (verification, sources, summary) share the same palette and typography through their stylesheet, so the data pages feel like part of the site rather than an appendix.
  • Practical details. Responsive layout down to phones, a skip link, keyboard-visible navigation, and no layout dependency on JavaScript for navigation.

Design decisions with an official source behind them

These are not taste. Each choice below exists because a governing document or an official webmaster guideline says so; the source is linked per row. (Where a rule was transcribed into the compliance ledger by an earlier session and re-verified 2026-11-14, this page links the official document rather than re-quoting it.)

DecisionWhy it is the safe choiceOfficial source
The disclosure sentence is rendered on every page, including this one. The Operating Agreement requires Associates to “clearly and prominently” state the exact sentence on their site. Operating Agreement §5
Outbound Amazon product links carry rel="sponsored". Google asks that paid or affiliate placements be marked with the sponsored value. Google — Qualify outbound links
No price is displayed anywhere on the site. Amazon restricts price display to links and API responses it serves itself; a static price goes stale and breaks the rule. Program Policies — Participation Requirements §2(b)
No star ratings or review scores are displayed. Customer reviews may be shown only when obtained through the Creators API / PA API, which this project cannot access yet (flag F-05). Program Policies — Participation Requirements §6(t)
Product cards link the canonical /dp/ listing as a citation, not the untagged short link as a purchase CTA. Special Links must properly use Amazon’s tagged link formats; an intermediate redirect that forwards the customer is a disqualifying link, and the supplied links carry no tag. Operating Agreement §1
The site name and branding contain no Amazon mark, and the footer states the site is independent. Amazon marks may not be used in domains, tags or identifiers; the relationship must not be misrepresented as an endorsement. Program Policies — IP License / Participation Requirements
Unverified values render as an explicit styled blank. The FTC standard: a material connection and the limits of a claim must be communicated clearly and conspicuously — quiet omissions are the classic failure mode. FTC Endorsement Guides

Suggestions queued for the next iteration — not implemented

Each idea below is written down so it can be chosen, amended or rejected on the suggestions decision board — the project’s rule is that a good idea ships only after someone records a decision. Nothing here is live in this release.

Conversion

Product landing pages per ASIN

Once the owner confirms the ASINs (F-01…F-03) and adds the Associates tag (F-24), give each product a dedicated conversion page — gallery, spec table, comparison table, single clear CTA — and make the root cards link there instead of straight to Amazon.

Blocked by: F-01…F-03, F-24. Sits behind the existing Counter Notes articles.
Catalog

Real product imagery via the Creators API

The Creators API can serve official product images once the account qualifies (ten qualifying sales in thirty days). Until then the pages run text-only, which is the compliant choice — scraping imagery is not.

Blocked by: F-05 (Creators API registration).
SEO

Structured data on published articles

Add Product / FAQ / Breadcrumb structured data to the Counter Notes articles after the tagging decision, so eligible rich results can appear. Needs the articles finalized first, because structured data must match visible content exactly.

Blocked by: F-03 (identity), F-24 (tagging).
Performance

Self-host the two fonts

Pages originally loaded Fraunces and Inter from Google Fonts. This concern was promoted from suggestion to implementation within the same release: the two families are now bundled in assets/fonts/ under their SIL OFL licence — no third-party request, fully self-contained.

Done in this release — kept on the board for the record.
Analytics

Switch on the privacy-minimal click counter

The first-party click tracker in tools/ (no cookies, no IPs, no visitor IDs) is built and dormant. It becomes meaningful the day tagged links exist; before that it counts nothing worth recording.

Blocked by: F-24 (tagged links).
Audience

An owned newsletter — built within the rules

Email placement of Special Links is permitted only for solicited communications under the Program Policies. A double-opt-in recipe newsletter around the air-fryer niche would be a compliant owned channel — but it needs real content cadence and an owner decision about operating it.

Owner decision required (operations, not code).

T46 — the front-of-house polish pass (2026-11-15, session 4b6b53e7)

The owner brief asked for a polished marketing presentation that does not read like generated filler, with the suggestion flow kept intact. What changed in this pass — same ledger, same gates, no value added, nothing hidden:

  • Corruption repaired. The live landing page carried merge debris — stray EAD lines, a stray in, and a duplicated footer link (introduced by the PR #88 merge; stray text broke no link-check, so the gates never saw it). Fixed here and recorded in docs/t42-redesign-2026-11-15.md.
  • One navigation, two tiers. Fourteen mixed links became seven primary destinations and a quieter evidence row (Verification, Sources, Flagged, Suggestions, Questions, Design notes), applied identically to every root page.
  • Product cards now lead with the verified specs. Each card renders the capacity, power and temperature rows from the same ledger the products page uses — every value with its source ↗ link to the official page. Price, rating and availability stay on the card as explicit blanks; the honesty is the differentiator, not a defect to hide.
  • The editorial got a front door. The three Journal pieces and the Counter Notes publication are surfaced directly on the landing page with their own words as teasers.
  • The commission KPI was de-ambiguated. The old card printed a single “4.00%” that could be misread as these products’ rate (irregularity R86-02). It now shows the two Table 1 bands (Kitchen 4.50%, All Other 4.00%) and states that which applies to the listings is open question Q-08.
  • Typography and rhythm tightened. Larger display scale for the hero and section titles, more air between sections, quieter table headers — presentation only; no claim, count, or source changed.

Queued by this pass — proposals awaiting an owner decision

Same rule as every suggestion here: options, a recommendation, and a status that stays “Proposed” until a choice is recorded on the decision board (design question SG-06).

Landing composition

Hero imagery vs. typography-only

Options: (A) keep the typographic hero — no image rights questions, loads instantly, unusual for the niche; (B) add manufacturer press images behind a verified licence check (open question Q-10 / discovery item D-03); (C) render an inline SVG spec-comparison graphic from ledger data (sourced, no rights questions).

Proposed — awaiting owner decision. This pass shipped A, the safe default; C is the recommended next step because every shape it draws traces to a ledger row.
Conversion

Where the primary CTA points

Options: (A) “Meet the three products” → products.html (shipped); (B) straight to the Journal for a softer editorial entry; (C) per-product landing pages once ASINs are confirmed (the existing suggestion, still blocked by F-01…F-03, F-24).

Proposed — awaiting owner decision. Evidence to decide with: Search Console behaviour after first index (discovery item D-01).
Evidence UX

A dedicated “Flagged” summary strip per section page

Options: (A) keep flags concentrated on flagged.html and the landing preview (shipped); (B) add a compact per-page flag strip to products/analysis so the caveat travels with the data.

Proposed — awaiting owner decision. B touches generated-adjacent surfaces and should follow the one-decision-store rule (DP-28).
Voice

Apply the T46 tone pass to the generated views

The landing’s tighter prose style could be carried through pages/, decisions/ and the generated views — a generator change, owned by tools/, and therefore a decision for the generator’s owner, not a CSS pass.

Proposed — awaiting owner decision. Must ship with its gate replay (build_site --check, validate_data).

What we already shipped quietly

Two small, standard webmaster-hygiene files now exist at the site root — they require no decision because they state nothing and can never drift into a claim:

  • robots.txt — allows crawling of everything and points at the sitemap.
  • sitemap.xml — the root pages and the findings hub, so crawlers see the structure without guessing.

How a suggestion becomes a change

The path is deliberately short and deliberately manual:

  1. Recorded — the idea lands on the decision board (pages/suggestions.html) with options, trade-offs and a recommended path, or in this design-notes queue.
  2. Unblocked — the open-questions register (pages/questions.html) shows which questions must be answered first; each question names how it could be closed and what it blocks.
  3. Chosen — the owner records the decision in the board’s decision field. No decision, no implementation.
  4. Built & verified — the change is implemented on its own branch, gated by the same line-by-line sourcing rules as everything else, and published through the verified pipeline.
