PRIVACY & MEASUREMENT

Measure the page. Not the person.

A narrow, first-party measurement design: aggregate events, no reader IDs, and no invented purchase attribution. Updated 19 November 2026.

What is active on GitHub Pages?

The published Pages configuration disables event collection. No counter events are transmitted or stored in browser storage. GitHub Pages is static hosting and cannot run our writable collector. The collector is implemented, but a permanent owner-controlled host is not provisioned. GitHub · GH-PAGES ↗

What changes on a self-hosted deployment?

When the complete site runs with our same-origin collector, the browser can send a visible page-load event, a click on a marked Amazon product link, and an observed disclosure-strip intersection. Only registered page paths, a static product label, a broad referrer category and a daily count are stored. No cookies, localStorage, fingerprints, reader/session identifiers, raw referrers, search strings, email addresses or IP/user-agent fields are written by the counter.

Do Not Track and Global Privacy Control disable collection. Browser events are not retried or persisted on your device. A failed count must not stop you following a link. A disclosure event is not proof of individual compliance, and counts are not unique readers or sessions.

Optional operator review preferences

The Suggestions page can save the operator’s explicitly selected proposal options in localStorage and export them on request. Those choices never leave the browser automatically, are not used by the analytics counter, and can be cleared on that page. No reader identifier is generated.

Network metadata and other companies

The hosting and network infrastructure necessarily receives connection information. GitHub states that it logs visitor IP addresses for security. A future reverse proxy or analytics host must have its logging configured and reviewed; we cannot promise that every infrastructure provider stores no network data. Amazon’s own policies apply when you follow a link there. GitHub · GH-PAGES ↗

Retention and reports

The self-hosted counter’s retention is 90 days for daily aggregates and imported report periods; deployments must run the documented daily prune task and apply the same limit to backups. No public endpoint exposes statistics. Purchase information can only come from an authorized first-party Associates report, not from watching a click. Search query reports require authorized Search Console access and a reviewed non-personal topic allowlist.

No blanket legal assurance

This describes the engineering and the current deployment state, not a determination of GDPR, ePrivacy, CCPA or other legal compliance. The site operator’s identity, jurisdictional assessment and privacy-contact process require review before a permanent analytics rollout. These gaps are on the Flagged for Review page.
