DESIGN BRIEF · 2026-11-19

The brief, written as a prompt you can hand over.

This is the design direction the Decision Room feeds. It is written to be pasted verbatim into a design session, so it states constraints rather than adjectives, and it names the decisions that must be answered before each change can be made.

The prompt

Build this site to look and read like a small, confident kitchen publication — not a compliance dashboard. Concretely:

1. One page template. Every page shares the same masthead, the same single affiliate disclosure strip directly under it, and the same footer. No section gets its own chrome.
2. The reader's task comes first on every page: what this appliance is, who it suits, what it does not do, and the questions to ask before buying. Publisher process material lives in the footer and never in the masthead.
3. The header carries at most five reader links. Every owner-facing dashboard is reachable from one collapsed group in the footer.
4. Product pages carry a sourced specification table where every row ends in an official link, a dash with a written reason, or an explicit conflict with both readings. No value is filled in to make a table look complete.
5. One paid-link control per product, marked as a paid link in its own text, carrying rel="sponsored nofollow noopener", and large enough to tap comfortably on a phone.
6. No price, no star rating, no review count, no demand claim, no revenue projection. Where a reader would expect one, say where to find it on the listing instead.
7. Original photography or none. Never an Amazon image, never a stock product photo, and never a caption that apologises for the image above it.
8. One URL per answer. If two pages answer the same buyer question, one of them is the page and the other is a redirect.
9. Type and spacing that hold up at 390px: no clipped table labels, no hidden navigation, no horizontal scroll except in a table that says it can scroll.
10. Every published claim links to the document that states it. A reader should be able to check any sentence in two clicks.

Constraints that are not negotiable: the Associates disclosure sentence appears above the fold and again in the footer on every page; every product link is sponsored-tagged; no price is printed; no number is invented.

Open decisions this brief depends on (each must be answered before the matching change):
  - DR-01 (Findability): Two different shop home pages are live. Which one should exist? Recommendation: option A — Outside repeated chrome, 17 main-content pages point to shop/index.html versus 2 to shop.html, and the shop-local categories and product pages sit under shop/index.html. Keeping it is the least disruptive recommendation; the canonical URL remains an owner decision.
  - DR-02 (Findability): The deepest verified content on this site is invisible to search engines. Should it be indexed? Recommendation: option A — The noindex boundary was drawn to keep operator dashboards out of search, and it does that. But it also swept up the most substantive reader pages, which is the opposite of the intent. The sourcing gates already exist and run over shop/**.
  - DR-03 (Findability): The packaged site exposes three RSS URLs, each serving the same five root-guide items. Which endpoint should it advertise, or should each endpoint carry distinct content? Recommendation: option A — The package currently publishes the same five-item document at three URLs. One advertised root feed is the simplest recommendation; if the owner wants section feeds, the build should generate genuinely distinct item sets. No endpoint is removed by this record.
  - DR-04 (Craft): Two chrome systems are live on one site. Should the shop pages look like the publication? Recommendation: option A — The root publication chrome is the better of the two and is what the brief asked for when it said the site should read like a publication. Two systems is the most expensive option over time, and it is already producing visible inconsistency between neighbouring pages.
  - DR-05 (Findability): Four shop guides repeat four root guides at different URLs. Which one survives for each pair? Recommendation: option A — A one-URL-per-question rule avoids maintaining overlapping entry points, but the longer page is not automatically the better one. Compare the sourced evidence and reader task pair by pair before selecting the retained page and redirecting its counterpart; this recommendation does not apply any redirect.
  - DR-06 (Craft): Each current publication page places 70 Workspace links in the masthead group and repeats the same 70 in the footer. How many does a reader need? Recommendation: option A — The brief asks that dashboards remain reachable from the footer and a simple navigation group. A 70-link disclosure in the masthead satisfies literal reachability but overwhelms the reader-facing navigation.
  - DR-08 (Findability): Which buyer questions bring readers? Nobody can answer that yet. Recommendation: option A — The brief asks that the next topic be chosen from measured queries rather than instinct. Without a verified property there is nothing to choose from, and no honest way to report progress.
  - DR-09 (Trust): The site writes confidently about five products nobody has confirmed were the ones the brief meant. Recommendation: option A — This is the highest-value five minutes available to the project. Every product page currently rests on an observation, and the site says so on every one of them.
  - DR-10 (Trust): The site carefully says it has not tested anything. Is that permanently true? Recommendation: option C — Buying five products before the site has a single measured visitor is the wrong order. Staying source-led is honest and already disclosed; the question is whether it is a strategy or a stopgap, and that should be written down.
  - DR-11 (Craft): The hero image says, in print, that it is AI-generated. Should it? Recommendation: option A — A site that advertises its own artificiality in the hero is telling the reader to discount it. The caption is honest and should stay until there is a real photograph to replace it — but the replacement is the point.
  - DR-12 (Craft): One of four reader links disappears below 550px. Should all four fit? Recommendation: option C — Measured honestly, this is the weakest row on the page: the destination is reachable from the disclosure strip and the footer on the same screen. Recorded so it is not rediscovered later, but it should not displace real work.

Copy the block above exactly. It contains no claim about search volume, conversion or revenue, because none has been measured.

The seven principles behind it

  • One template for the whole site. Two design systems is how a publication starts to look assembled.
  • Lead with the product and the buyer's question. The verification method is the footnote, not the headline.
  • One URL per answer, one feed, one shop.
  • Source every claim, and print the dash and the reason when there is no source.
  • The disclosure is above the fold and in the footer, on every page, always.
  • No price, no rating, no demand claim, no forecast — and say where to look instead.
  • Original photography or the honest caption. Never an Amazon image.
