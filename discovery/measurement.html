The rules a measurement layer has to survive

Written first, because they rule out most of the obvious designs. Each is anchored to the official page that constrains it.

From docs/measurement-t40.json. A design that violates one of these is not implemented, however useful the data would be.
IDRuleOfficial source
MP-01No personal data, no cookie, no cross-site identifier, and no identifier derived from a visitor.
Amazon's Participation Requirements forbid associating a sub-tag or reporting ID with a specific end user (R-08 in ledger/compliance.json; S02 in ledger/sources.json). A design that cannot do that even if asked is stronger than a policy that says not to.
S46 · AmazonAssociates Program Participation Requirements, Sections 6(v) and 6(w)
MP-02Measure the page and the link, never the person.
The only questions this site needs answered are 'which page sends people to which product' and 'which page earns'. Both are aggregate counts on a page-plus-link key. Nothing about an individual changes any decision the owner can make.
no official source
MP-03Publish no traffic, conversion or income expectation, and no forecast.
The Operating Agreement states that Amazon makes no representation or warranty regarding the amount of traffic or commission income an Associate can expect (S58). A projection on this site would present as knowledge exactly what that clause disclaims. The layer records what happened; it never prints what will.
S58 · AmazonAssociates Program Operating Agreement, Section 4 - no representation
MP-04Every event has a stated decision it supports, or it is not collected.
Measurement without a decision is cost with no benefit. This file therefore lists the decision beside each event, and the gate refuses an event with no decision.
no official source
MP-05Search measurement must not route visitors straight to Amazon.
Search results, paid or unpaid, must send users to the site and not directly or indirectly to an Amazon Site (S51). Any Search Console or paid-search plan is constrained by that.
S51 · AmazonAssociates Program Participation Requirements, Section 6(f) - search t

What is still unresolved before anything could be collected

  • MI-01 — Self-hosted collector implemented and tested, but no owner-controlled production HTTPS endpoint/reverse proxy is provisioned. GitHub Pages is static; production config remains disabled. Affects EV-01, EV-02, EV-03
  • MI-02 — Implemented default: 90-day rolling retention, purged on ingestion/export and by a scheduled purge command. Confirm hosting logs, lawful basis and operator notice before production activation. Affects EV-01, EV-02, EV-03
  • MI-03 — Basic automation exclusion in the client and a global request budget in the service are implemented. Origin validation is not human authentication; sophisticated bots can still inflate counts. No unique-human, session, or conversion-rate claim is made. Affects EV-01
  • MI-04 — There is no way to verify a click led to a purchase from this side, and this project must never imply there is. Attribution is Amazon's to report, not this site's to guess. Affects EV-04

Privacy, stated carefully

The implementation uses no browser storage, cookies, visitor identifiers, IP persistence, or full referrers. It honors Global Privacy Control and Do Not Track. This is an engineering minimization choice, not an exemption from privacy or consent law.

Only properties enforced by the implementation and tests. GitHub and any reverse proxy may independently process addresses; configure and disclose host-level processing separately.

What this page does not claim. No claim is made about GDPR, CCPA or any specific jurisdiction's requirements, and none should be inferred from this file. Whether a cookie-free aggregate counter falls inside or outside a particular regime is a legal question the owner must put to their own adviser. Recorded as a gap, not an answer.

What remains outside this repository’s authority

Provisioning an owner-controlled HTTPS collector host, confirming the enrolled Associates account, validating one destination and tracking report per product, and verifying Search Console all require authorized infrastructure or account access. Those gates remain open; no visitor is silently redirected and no browser event is ever presented as a purchase.
