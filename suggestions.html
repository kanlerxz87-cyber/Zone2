SG-T50-01

Lead with the products, not with the verification process

Proposed - awaiting owner decision

Area: Site design · The landing page that shipped before this pass opened with how many links resolved and how many were confirmed. That is operator reporting, and a reader arriving from search does not care. This pass moves the products, the verdicts and the articles above the fold and demotes the verification state to a single strip. No verified value moves or changes.

Option A

Keep the operator dashboard as the landing page and put the publication one click away.

Cost No build cost
Trade-off Readers arriving from search bounce on a page that talks about process instead of products.
Option B  (recommended)

Rebuild the landing page as a publication front page; keep every dashboard surface reachable from the footer and a single navigation group.

Cost One pass, no data change
Trade-off The owner loses the at-a-glance verification state on the first screen; it moves to a strip lower down.
Option C

Split into two separate sites with two separate domains.

Cost Two codebases, two deploys
Trade-off Doubles the maintenance and splits whatever authority the domain earns.
Recommended Option B Waits on none — this can be decided now Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-02

Put an Associates tag on every product link

Proposed - awaiting owner decision

Area: Revenue · Amazon's own help page gives the qualifying link format as http://www.amazon.com/dp/ASIN/ref=nosim?tag=YOURASSOCIATEID. None of the three links supplied carries a tag parameter, so as supplied they cannot attribute a sale to any Associates account. Until a tag exists every outbound link on this site is a preview link marked rel="sponsored nofollow" and earns nothing.

Option A

Leave the links untagged and label them plainly as non-monetised preview links.

Cost None
Trade-off The site cannot earn. Everything downstream - click tracking, conversion, optimisation - stays theoretical.
Option B  (recommended)

Ask the owner for the Associates ID and marketplace, then regenerate every link through the existing link builder with the tag applied.

Cost One configuration value
Trade-off Requires the owner to supply a credential this project must never invent.
Option C

Register a new Associates account for this project.

Cost Application + review
Trade-off Amazon reviews the site before approval; see the application-review criteria.
Recommended Option B Waits on Q-T50-02, Q-T50-03, Q-T50-04 Source Amazon: How do I build a simple text link to a specific item on Amazon? · affiliate-program.amazon.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-03

Confirm the three products inside Associates Central

Proposed - awaiting owner decision

Area: Identity · Each supplied link resolves, reproducibly, to one live Amazon listing. That destination is an observation of the link's behaviour, not a statement about what the brief meant: the supplied codes are nine characters, an Amazon ASIN is ten, and no public Amazon document binds a short-link code to a product. Confirming the three ASINs inside the Associates account is the only step that turns 'the listing this link opens' into 'the product this campaign promotes'.

Option A

Keep writing destination-first: describe the listings the links open and say on every page that the mapping is unconfirmed.

Cost None
Trade-off Honest, but every article is one ASIN correction away from being about the wrong product.
Option B  (recommended)

Have the owner open the three links while signed in to Associates Central and record the ASIN each one lands on, then re-verify against the Creators API.

Cost Ten minutes of owner time
Trade-off None. This is the cheapest unblock available.
Option C

Re-supply the three products as full ten-character ASINs or complete product URLs.

Cost One message
Trade-off Discards the short links, which may carry tracking the owner wants.
Recommended Option B Waits on Q-T50-01 Source Amazon: How do I build a simple text link to a specific item on Amazon? · affiliate-program.amazon.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-04

Publish question-shaped guides, then measure whether anyone arrives

Proposed - awaiting owner decision

Area: Organic traffic · The eight published guides are built around the questions a buyer actually types - how many quarts, two baskets or one, will it fit, does the Hi-Fry number mean anything - rather than around product names. That is the shape Google's own guidance rewards: it describes helpful content as content created for people, and it names thin affiliate pages with no added value as a spam pattern to avoid. Demand and search-volume figures for these topics are left blank everywhere on this site: no official source states them and guessing them is exactly the failure mode the guidance warns about.

Option A

Stop at the eight guides already published.

Cost None
Trade-off Eight pages is a small surface for a search engine to find.
Option B  (recommended)

Set a publishing cadence, add each new guide to the existing sitemap and feed, and turn on real analytics so the next topic is chosen from measured queries instead of instinct.

Cost Recurring writing time
Trade-off Needs analytics to be genuinely useful rather than decorative.
Option C

Buy keyword-volume data and pick topics purely on volume.

Cost Paid tool
Trade-off Volume data is third-party, not an official source; under this project's rule it cannot be published as fact.
Recommended Option B Waits on Q-T50-08, Q-T50-11 Source Google - Creating helpful, reliable, people-first content · developers.google.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-05

Turn on click and conversion measurement before writing anything else

Proposed - awaiting owner decision

Area: Measurement · Five events are defined in the measurement plan and zero are live, because the site is static and nothing records an outbound click. Without them every optimisation decision is a guess. The measurement page states this plainly rather than presenting a dashboard of invented numbers.

Option A

Leave measurement off and keep saying so.

Cost None
Trade-off No campaign can be optimised, which is a core requirement of the brief.
Option B  (recommended)

Add a privacy-preserving outbound-click counter and a self-hosted analytics endpoint; record the five defined events.

Cost Small build
Trade-off Needs a hosting decision - GitHub Pages serves static files only.
Option C

Use Amazon's own reports as the only source of truth and infer on-site clicks from them.

Cost None
Trade-off Amazon reports purchases, not the clicks that preceded them, so the funnel stays half invisible.
Recommended Option B Waits on Q-T50-08, Q-T50-10 Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-06

Settle which commission band actually applies to these three listings

Proposed - awaiting owner decision

Area: Revenue · Table 1 of the Standard Commission Income Statement lists Kitchen at a fixed 4.50% and All Other Categories at 4.00%. All three resolved listings sit in the Air Fryers browse node, which is inside Home & Kitchen - but the band that applies to a given ASIN is a property of the listing, not of the browse path, and only the Associates account can read it. The site publishes both figures and marks the choice as open rather than picking one.

Option A

Assume 4.50% because the browse path says Kitchen.

Cost None
Trade-off The browse path is not the rate field. Publishing an assumed rate is the kind of value this project refuses to invent.
Option B  (recommended)

Read the rate per ASIN from the Associates account or the Creators API and store it as a verified row.

Cost One authenticated lookup
Trade-off Needs the Associates credential.
Option C

Publish both bands and the condition that separates them, permanently.

Cost None
Trade-off Accurate but stalls any revenue model that needs a single number.
Recommended Option B Waits on Q-T50-05, Q-T50-02 Source Associates Program Standard Commission Income Statement (Table 1) · affiliate-program.amazon.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-07

Keep the disclosure above the fold on every page, including this one

Proposed - awaiting owner decision

Area: Compliance · The Operating Agreement requires the affiliate disclosure to be clear and conspicuous; the FTC's guidance for influencers says the same in plain terms - disclose it where people will actually see it, not buried at the bottom. Every page in this build carries the disclosure in a strip directly under the masthead, before any product content.

Option A

Footer-only disclosure, as most affiliate sites do.

Cost None
Trade-off Fails the 'clear and conspicuous' standard the agreement and the FTC both set.
Option B  (recommended)

Disclosure strip under the masthead on every page, repeated in the footer.

Cost None
Trade-off Costs about forty pixels of above-the-fold space.
Option C

Disclose once on a dedicated page and link to it.

Cost None
Trade-off A reader who lands on a product page never sees it.
Recommended Option B Waits on none — this can be decided now Source FTC - Disclosures 101 for Social Media Influencers · ftc.gov Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-08

Keep every outbound product link marked as sponsored

Proposed - awaiting owner decision

Area: Compliance · Google's guidance on qualifying outbound links says links that are part of a paid arrangement should be marked so the paid relationship is not passed to search engines. Every product link in this build carries rel="sponsored nofollow", and the deploy gate fails the build if a page stops doing it.

Option A

Mark only some links, or mark them after the site starts earning.

Cost None
Trade-off Inconsistent markup is the exact pattern the guidance is written against.
Option B  (recommended)

Mark every outbound product link now and keep the check in CI.

Cost None
Trade-off None.
Recommended Option B Waits on none — this can be decided now Source Google - Qualify your outbound links to search engines · developers.google.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-09

Never publish a price, and say on the page why the price is missing

Proposed - awaiting owner decision

Area: Content · The program policies restrict displaying prices to content Amazon itself serves through links or API responses. Manufacturer pages do list prices; this site still publishes none. A reader who sees a dash instead of a price needs one sentence explaining it, otherwise the dash reads as broken research rather than as a rule being followed.

Option A

Show the manufacturer's list price with a note that it may differ from Amazon's.

Cost None
Trade-off Breaks the program policy the rest of the build is designed around.
Option B  (recommended)

Print a dash with a one-line reason beside it, and link to the policy that forces it.

Cost None
Trade-off Some readers will still leave to check the price.
Option C

Render prices only inside an official Amazon widget the account is entitled to use.

Cost Widget configuration
Trade-off Depends on an approved Associates account and on the widget being available for the marketplace.
Recommended Option B Waits on Q-T50-06 Source Amazon Associates Program Policies · affiliate-program.amazon.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-10

Decide whether this is a three-product site or a category site with three products in it

Proposed - awaiting owner decision

Area: Catalogue · Everything published so far covers three air fryers. The platform brief asks for niche discovery at scale - trending products, competition analysis, continuous optimisation - which is a different shape of site than three hand-checked reviews. Which one this is determines whether the next unit of work is a fourth article or a research pipeline.

Option A

Stay a three-product review site and make it excellent.

Cost None
Trade-off Leaves most of the platform brief - automation, niche discovery, scale - unbuilt.
Option B  (recommended)

Treat the three as the seed set: build the research pipeline next, and let it propose the fourth through the twentieth product via this same decision board.

Cost Pipeline build
Trade-off Needs the Creators API credential; PA-API 5.0 is deprecated and no longer the route in.
Option C

Expand by hand, one product at a time, on owner request.

Cost Writing time per product
Trade-off Does not scale to the automation the brief asks for.
Recommended Option B Waits on Q-T50-12, Q-T50-07 Source Creators API - PA-API 5.0 deprecation notice · affiliate-program.amazon.com Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-11

Set a re-verification cadence and print the date on every page

Proposed - awaiting owner decision

Area: Freshness · This pass found a real drift: the Amazon listing title stored in the record for the 26-quart Emeril oven is no longer the title Amazon serves. The specification rows were unaffected, but a record that is never re-read will eventually be wrong. A stated cadence plus a visible 'last checked' date is what keeps a sourced site honest over time.

Option A

Re-verify only when something looks wrong.

Cost None
Trade-off Drift is invisible until it matters.
Option B

Re-read every official source on a fixed schedule, record what changed, and print the date on the page.

Cost Recurring verification time
Trade-off None beyond the time.
Option C  (recommended)

Automate the re-read and fail the build when a recorded quote no longer appears on the source page.

Cost Build + scheduled runner
Trade-off Needs a scheduler; GitHub Actions can do this on a cron.
Recommended Option C Waits on Q-T50-11 Implemented No — no suggestion on this board is applied until a choice is recorded.
SG-T50-12

Hold the writing to a standard the build can enforce

Proposed - awaiting owner decision

Area: Site design · The brief's complaint was that the site read as generated. The fix is not a different tone - it is a rule set the build can fail on: no scene-setting opener, no adjective where a number belongs, no recycled manufacturer copy, opinion in a labelled box away from the measurements, and every number traceable to a page a reader can open. The existing verification scripts already enforce several of these; this suggestion is to keep them and to add the ones that are still only habits.

Option A

Treat writing quality as a review-time judgement.

Cost None
Trade-off Judgement drifts, especially when the volume rises.
Option B  (recommended)

Keep the enforced rules, publish the full rule set on the method page, and negative-test each one so the check cannot quietly stop firing.

Cost None
Trade-off Rules constrain phrasing, which some writers find limiting.
Option C

Generate articles without a rule set and edit afterwards.

Cost None
Trade-off This is the failure mode the brief is complaining about.
Recommended Option B Waits on none — this can be decided now Source Google - Using generative AI content on your site · developers.google.com Implemented No — no suggestion on this board is applied until a choice is recorded.
